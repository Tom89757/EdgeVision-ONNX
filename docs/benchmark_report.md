## 2. 测试方法

- 模型：`mobilenet_v2_fp32.onnx` 与 `mobilenet_v2_int8_qdq.onnx`。
- Execution Provider：CPU 1 线程、CPU 2 线程、CPU 4 线程、XNNPACK、NNAPI。
- 每条配置先单独加载 Session，记录冷启动耗时；随后记录首帧。
- 首帧之后预热 **5 帧**，再连续测量 **50 帧**。
- 稳态统计使用这 50 帧，p50 / p95 采用 nearest-rank，不包含冷启动、首帧和预热帧。
- 单帧耗时定义：

  `端到端总耗时 = 预处理耗时 + 纯推理耗时 + 后处理耗时`

  - 预处理：`Preprocess.fromBitmap()`，包含 ORT 输入 Tensor 构造。
  - 纯推理：一次 `OrtSession.run()`。
  - 后处理：提取 logits、执行 Top-K（K=5），并释放 Result/输入 Tensor。
- 冷启动：资产大小/SHA-256 校验、模型字节读取、Session 创建，不包含 Activity 启动。
- 首帧：Session 加载完成后的第一次完整分类。
- PSS：每条配置完成 50 帧后读取应用进程总 PSS，包含当前 Session 的内存占用；
  测量后立即释放 Session，再进入下一配置。
- 输入：App 内生成固定的 640×480 ARGB_8888 合成图，复用同一 Bitmap 以排除相册
  解码和文件 I/O 波动，再由统一预处理缩放到 224×224。

### 5.2 必须诚实说明的限制

- **NNAPI 已进入 deprecated 阶段。** Android 15/16 起 NNAPI 官方已标记 deprecated，
  新代码不应把 NNAPI 当作唯一加速路径；部分设备/系统版本可能行为不同，必须保留
  CPU 回退并在 JSON 的 `actual_provider` 中记录真实状态。
- **实际 Provider 可能不是完整图执行。** 不同 OEM 驱动和 ONNX Runtime 版本的算子
  覆盖不同，NNAPI 等 EP 可能只接管部分子图，其余节点回退 CPU，导致图切分、额外
  数据搬运和上下文切换。请求 NNAPI 不代表整张模型在 NPU 上运行。
- **INT8 QDQ 存在反量化开销。** QDQ 模型权重更小、内存带宽压力可能降低，但 CPU
  kernel 仍需执行 Dequantize/Quantize 及相邻算子，未必比 FP32 更快。文件更小也
  不等于端到端延迟更低，应同时看预处理、纯推理、后处理和 PSS。
- **线程越多不一定越快。** 小图 MobileNetV2 在部分设备上可能受调度、功耗墙、热降频
  和大核唤醒影响；应重点观察 p95 与连续多轮稳定性，而不是只看单次最好成绩。
- **首帧与冷启动受系统状态影响大。** 资产 SHA-256 校验、模型读取、页缓存、CPU 调频
  和后台负载都会影响这两个指标，不能与稳态推理耗时混为一谈。
- **合成图只控制输入波动。** 它避免相册解码差异，适合横向比较，但不代表真实相册
  图片或 CameraX 帧转换的完整成本；CameraX 相关 I/O 需要在业务链路上另行测量。
- **PSS 是进程级观测。** 它包含 Activity、Bitmap、运行时和当前模型 Session，不能
  直接等同于单个模型的权重内存；不同配置间应保持测量时点一致。
- **本文不得填写估算值。** 未在上述环境中实际运行产生的数字一律保持占位符。

## 6. 导出与复现

1. 打开 App，完成启动资产校验。
2. 进入「多后端 Benchmark」，点击「一键开始跑分」。
3. 跑分完成后点击「导出 JSON」，页面会显示应用私有目录中的绝对路径。
4. 使用 `adb pull <页面显示的绝对路径> .` 取回 JSON。

JSON 包含设备信息、测试方法、每条配置的 `actual_provider`、冷启动、首帧、
阶段 p50/p95、端到端 p50/p95 与 PSS。完整 JSON 应作为本报告的附件保存。
